1 · Connect a source

Open /new. You can start four ways:

  • Import a repository. Sign in with GitHub or Bitbucket, search your repositories — private and organization repos included — and press Import.
  • Public repository URL. Paste an https:// URL on github.com, gitlab.com or bitbucket.org. Aibotq checks the repository exists before continuing.
  • Upload. Drop a folder or a .zip. Limits: 50 MB and 1000 files; node_modules, .git and .env* are skipped. Uploads require an R2 bucket bound to the Worker.
  • Template. Agent App, AI Chatbot and Commerce Agent are template repositories ready to deploy.

3 · Deploy

Press Deploy to edge. Aibotq validates plan quotas, rate limits (10 deploys / 10 minutes), records the deployment in D1, and dispatches a signed HMAC request to the pipeline. The dashboard and chat assistant monitor live states — Queued → Building → Live.

Instant deployment rollbacks

You can roll back the live production URL to any previous ready deployment with zero rebuild time.

  • Retention Guard: Rollbacks are allowed to deployments created within the last 7 days.
  • Zero Rebuild: Re-points the live URL instantly in D1 and sends a signed rollback event to the build pipeline to restore the stored artifact without compiling.
  • Audit Trail: Rollbacks generate a deployment history record with a distinct Rollback to #<id> badge.
  • API: POST /api/projects/:id/deployments/:did/rollback.

Build from chat (bot-aware deployments)

The Aibotq assistant in /chat is directly connected to the deployment pipeline and D1:

  • Live Status: Ask "สถานะ build ล่าสุดคืออะไร" or "What is the build status?" and get real-time status.
  • Failure Diagnostics: Ask "build ล้มเหลวเพราะอะไร" — the bot reads the real build log from D1, pinpoints the failing step, quotes the error lines, and suggests a concrete fix.
  • Chat Tools: deploy_project, list_deployments, get_build_log, rollback_deployment, and set_env_var (write-only; secret values are never echoed back).
  • Access Control: Only project owners and team members can trigger builds or rollbacks.

Enterprise SAML 2.0 SSO

Organizations on the Team plan can configure SP-initiated SAML single sign-on with any SAML 2.0 Identity Provider (Okta, Entra ID / Azure AD, Google Workspace, OneLogin):

  • SP Metadata Endpoint: GET /api/auth/saml/metadata
  • Assertion Consumer Service (ACS): POST /api/auth/saml/acs
  • Security: Clock-skew tolerance ≤ 5 minutes, signed assertions, encrypted credentials and IdP metadata stored in D1.
  • Just-In-Time (JIT) Provisioning: New team members are automatically provisioned with roles mapped from IdP group attributes upon initial login.
  • Fallback Identity: GitHub OAuth remains linked as a fallback login.

Monorepo multi-app support

A single Git repository can contain multiple root applications, each with independent framework detection, build commands, and output directories.

App NameRoot DirectoryFrameworkBuild CommandOutput Dir
webapps/webNuxtnpm run build.output
apiapps/apiNode / Hononpm run builddist
docspackages/docsAstronpm run builddist

Path-Filtered Deploys: When commits are pushed to GitHub or Bitbucket, Aibotq inspects the list of changed files. A commit that only modifies apps/web/src/pages/index.vue only triggers a deployment for the web app, saving build minutes and compute time.

Git push & webhooks (GitHub & Bitbucket)

Webhooks are automatically registered for GitHub and Bitbucket repositories:

  • Pushes to the default branch trigger production deployments.
  • Pull requests opened, synchronized, or reopened trigger preview deployments with isolated URLs.
  • Pull requests from forks are strictly ignored to prevent untrusted code execution.
  • Webhook signatures are verified using HMAC-SHA256 secrets.

Environment variables

Up to 64 variables per project, encrypted at rest with AES-GCM. Variables are write-only: secret values are never returned by the API or echoed in chat responses.

Build pipeline contract

Build requests are signed with HMAC-SHA256(DEPLOY_WEBHOOK_SECRET, "<timestamp>.<raw body>") in header x-aibotq-signature. Rollbacks send x-aibotq-event: rollback with the target artifact ID.
